成果物としては:
- `outputs/daily-stock-data-2026-05-23.MOCK.json` (mock 入力ベースの統合 JSON)

### 誤検出耐性チェック (全部 PASS)

- `$5B+` → 除外 (dollar-amount regex)
- `US` → 除外 (exclude_words)
- `EPS`, `ATH` → 除外 (exclude_words)
- `$NVDAx` / `$TSLAx` → `\b` 境界で uppercase 部分のみ取れず、token symbol 自体は ticker としては抽出されない (= 意図通り。 underlying ticker `NVDA` `TSLA` への join は `tokenized-issuers.json` で行う)

### 検出して正解した銘柄

- **VELO / RDW / BKSY / GHM** (The Assembly が言及した宇宙・防衛小型株) — まさにこの企画が拾うべき "ニッチ" 銘柄。S&P500 中心 API では出てこない。
- **NVDA** が3つの onchain 発行体 (xStocks / Backed Base / Dinari) で同時にトークン化されていることが merge で可視化された → 「同じ NVDA を Solana / Base / Arbitrum でどう買えるか」を1リクエストで返せる構造。

### 未解決の挙動

- **VELO**: 文脈不明。NYSE の旧 Velo3D は2024年に上場廃止済み。The Assembly が言及するなら別企業 (例: 私募の Velo) の可能性。`unlisted-context-mock.json` に「ambiguous - context check required」と記録した。実装では yfinance がエラーを返した ticker は必ず WebSearch で文脈確認するプロセスを `enrich_tickers.py` に組み込む必要。
- **AMD/GHM/BKSY/RDW** が tokenized_versions=0 だが、これは `tokenized-issuers.json` の `known_tickers` がまだ Top 銘柄のみだから。`xStocks` は 131 銘柄、`Ondo` は 260 銘柄を扱うため、各発行体の **正式 ticker リスト全件** を data/tokenized-issuers.json に取り込む作業が次の優先度。

## 次のアクション

| # | タスク | 優先度 |
|---|--------|-------|
| 1 | `twitter` Skill OAuth 認証 → 実 post で再ラン | **High** (本番動作確認) |
| 2 | `yfinance-data` Skill 経由で `enrich_tickers.py` を実装 (現状は手作り mock) | **High** |
| 3 | `tokenized-issuers.json` の各発行体の `known_tickers` を全件展開 (xStocks 131, Ondo 260, Dinari 200, Backed Base ~10) | High |
| 4 | `unlisted-context-*.json` 生成も WebSearch agent で自動化 (`scripts/enrich_unlisted.py`) | Mid |
| 5 | x402 endpoint 設計 (Vercel 側 repo) | Mid |
| 6 | Backpack IPOs Onchain の `deals_pipeline` に実際の銘柄が乗ったら refresh する cron | Mid |
| 7 | rate limit 観察 (twitter API / yfinance) と x402 化候補リスト更新 | Low |

## 再現方法

```bash
# 1. Extract tickers from posts
python3 scripts/extract_tickers.py \
  --posts data/examples/sample-posts.json \
  --config config/watchlist.json \
  --output data/examples/extracted-tickers-mock.json

# 2. (本番では yfinance Skill で生成) MOCK enrichment はそのまま使用
# data/examples/yfinance-enrichment-mock.json
# data/examples/unlisted-context-mock.json

# 3. build_daily_dataset.py が data/ ディレクトリを参照するので、
#    examples のファイルをコピーして実行する場合:
cp data/examples/extracted-tickers-mock.json    data/extracted-tickers-2026-05-23.json
cp data/examples/yfinance-enrichment-mock.json  data/yfinance-enrichment-2026-05-23.json
cp data/examples/unlisted-context-mock.json     data/unlisted-context-2026-05-23.json
python3 scripts/build_daily_dataset.py --date 2026-05-23
# → outputs/daily-stock-data-2026-05-23.json (新規) / .MOCK.json (本コミットに含まれる固定版)
```

## 結論 (dry-run)

- パイプラインの **3 ステージ join (mentions × yfinance × tokenized × primary_issuance)** はスキーマレベルで動作。
- 正規表現 + exclude_words の組み合わせで、現状の watchlist 想定では誤検出率は十分低い (mock では false positive ゼロ)。
- 本番化のボトルネックは **`twitter` Skill OAuth と `yfinance-data` の rate limit / coverage**。
- `tokenized-issuers.json` の銘柄カバレッジ拡張だけは Skill を待たずに WebSearch で進められる (次セッション)。
